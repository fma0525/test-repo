# 論文摘要：A Process Simulation Model for a Histopathology Laboratory

- **作者**：Yin-Chi Chan、Anandarup Mukherjee、Nicola Moretti、Momoko Nakaoka、Jorge Merino、Zahrah Rosun、Colin Carr、Duncan McFarlane、Ajith Kumar Parlikad
- **單位**：英國劍橋大學製造研究所（IfM）、倫敦大學學院（UCL）Bartlett、劍橋 Addenbrooke's 醫院病理科
- **出處**：Proceedings of the 2024 Winter Simulation Conference，pp. 846–857（12 頁）
- **全文**：<https://informs-sim.org/wsc24papers/con133.pdf>
- **經費**：Cambridge University Hospitals NHS Foundation Trust

## 1. 研究動機

- 英國病理檢體量**每年成長 4.5%**，但病理專科醫師人數每年只增加 **1.2–3%**（Cancer Research UK 2016）。
- 2022/23 年度，NHS England 只有 **70.2%** 的病人在轉介後四週內拿到癌症診斷。
- 過去的醫院模擬模型都把病理科當成一個黑盒子，沒有拆開實驗室內部每一步，所以無法回答「人力該加在哪裡」「排班怎麼調」這類管理問題。
- 本篇的目標：以 Addenbrooke's 醫院為對象，建一個**拆到每個作業步驟**的離散事件模擬模型，用來評估人力、排班和 TAT 之間的取捨。

## 2. 資料來源與方法

- 資料來源：檢體流程的系統紀錄（log）、實驗室 SOP 文件、工作坊、現場觀察、人員訪談。
- 用來比對的 KPI 是英國皇家病理學院（RCPath）2013 年的 TAT 指引（排除送外會診的個案）：
  - **80% 的個案 7 個日曆天內發報告**
  - **90% 的個案 10 個日曆天內發報告**
- 論文定義兩種 TAT：
  - **整體 TAT**：收件到發出報告（9 個階段全部）
  - **實驗室 TAT**：收件到完成數位掃描（前 8 個階段）

## 3. 模型化的 9 個流程階段

| # | 階段 | 內容 |
|---|---|---|
| 1 | 收件 Reception | 依專科和優先序分類、登錄、核對病人資料；資料缺漏要額外查證 |
| 2 | 取材 Cut-up | 檢體切小放進卡匣。簡單切片由技術員（BMS）做，其他由專科醫師加取材助理做（模型只算取材助理的人力） |
| 3a | 脫鈣 Decalcification | 骨頭類檢體才需要。分烤箱酸浴、骨髓專用 bone station 兩種 |
| 3b | 脫水 Processing | 脫水機批次處理。**只有同一種程序的檢體能放同一批** |
| 3c | 包埋與修塊 | 每個卡匣做成一個蠟塊 |
| 4 | 切片 Microtomy | 切片、貼玻片、貼暫時標籤 |
| 5 | 染色 Staining | H&E 染色加封片。一般玻片由機器封片，特大玻片（mega）手工封片 |
| 6 | 貼標 Labelling | 貼永久標籤，由切片人員負責 |
| 7 | 掃描 Scanning | 玻片批次數位掃描 |
| 8 | 蠟塊與品質檢查 | 確認每個檢體的蠟塊和玻片都齊全，並檢查玻片品質 |
| 9 | 判讀 Reporting | 病理醫師看數位影像、發報告 |

整個流程是線性的，每個檢體依序走完 9 個階段。

## 4. 模型細節

**工具**：這篇論文的模型是用商用軟體 **Arena** 建的。GitHub 上的 Python（salabim）版本 `yinchi/histopath-bim-des` 是之後的延伸工作，用在 2025 年的期刊論文。

**到件**
- 癌症件、非癌症件各是一條「每小時到件率不同」的 Poisson 過程。

**人力與設備**
- 人力以**每 30 分鐘**為單位設定班表。
- 設備數量假設固定不變。

**作業時間**
- 大多用三角分布（最短、最可能、最長），數值來自 SOP 和人員訪談。
- 脫水程序這類機器作業用固定時間。

**檢體屬性**
- 是否為癌症路徑（影響優先序的機率）
- 院內或院外（影響收件流程和時間）
- 優先序：急件不參與站間批次運送，而且走較短的脫水程序
- 取材類型 3 種（決定由誰取材、產生哪種蠟塊）
- 蠟塊類型 3 種（決定蠟塊數）
- 蠟塊數（決定切片時間）
- 總玻片數（各蠟塊玻片數加總）

**論文特別處理的 5 個建模難題**
1. **站間運送（runner）**：送件的人員把檢體送到下一站後還要走回原站，這段時間也佔用人力。一般件會「湊批再送」，並設有最長等待時間；急件個別送，不等批。
2. **依蠟塊數湊批**：每台脫水機有蠟塊容量上限，**同一檢體的蠟塊不能拆到不同批**。只有同一程序的檢體能同批，程序分急件、小檢體、大檢體、特大四種。
3. **多重觸發條件**：脫水機在「下班時」啟動，或「湊滿一台」時啟動。下班時沒湊滿的也會組成一個不滿的批次一起上機。急件湊好就立刻上機，不等下班。
4. **熱啟動（hot start）**：可以從 Excel 讀入目前實驗室裡還在流程中的檢體，模擬從現況開始跑，用來做短期預測。
5. **單獨分析某一段流程**：例如只看包埋這一段，排除上游瓶頸的影響。

## 5. 實驗結果

### 實驗一：多加 1 名人力，加在哪一站最有效？

條件：額外人員都是 9:00–17:00 上班，12:30–13:30 午休；每個情境跑 10 次，取平均實驗室 TAT 和 95% 信賴區間（圖 5）。

| 情境 | 平均實驗室 TAT（小時） |
|---|---|
| 現況 | 129.28 |
| +1 收件人員 | 129.96 |
| +1 技術員（BMS） | 128.80 |
| +1 取材助理 | 125.97 |
| +1 脫水/包埋人員 | 130.41 |
| **+1 切片人員** | **121.28** |
| +1 染色人員 | 128.05 |
| +1 掃描人員 | 132.46 |
| +1 品管人員 | 125.52 |

- **只有「+1 切片人員」讓 TAT 有統計上顯著的下降**：129.3 → 121.3 小時，約少 8 小時，降 6%。
- 加在其他站的差異都落在信賴區間內，等於沒效果。
- **意涵**：人力要加在真正的瓶頸站，加在非瓶頸站幾乎沒有用。這就是限制理論（TOC）的典型結果。

### 實驗二：N 個蠟塊包埋要多久？

- 這是病理科實際提出的問題：「包埋 N 個蠟塊需要幾小時？」
- 做法：只保留包埋這一段，忽略班表，人數固定，一次放入 N = 400 個蠟塊，每個情境重複 500 次。
- 每個蠟塊平均 90 秒（包埋 60 秒 + 修塊 30 秒），所以每人每小時約 40 塊，期望完成時間 = N × t / m（m 為人數）。測了 2 到 5 人。
- 完成時間呈常態分布（Shapiro-Wilk 檢定 p > 0.05）。
- 這個數字是**理論下限**。真實系統還會受上游瓶頸、排班和其他工作影響。

## 6. 作者自述的限制與未來方向

1. **Arena 很難換參數跑多情境**。每改一次班表（陣列參數）就要複製一份模型，圖 5 的每個情境都是一份獨立的模型檔。
2. **Arena 不是物件導向**，很難表達「檢體 → 蠟塊 → 玻片」的從屬關係，批次處理後蠟塊和玻片的資訊會遺失。
3. 到件目前用 Poisson 過程，但實際是**物流人員批次送達**。未來想串接院內檢體物流模型。
4. **沒有考慮次專科分工**，例如取材和判讀依組織類型由不同醫師負責；取材也沒算專科醫師的人力。
5. **優先序只做了一部分**。大多數佇列是先到先做，改成依優先序排隊應該能提高準確度。

## 7. 對我們規劃病理中心的啟示

| 論文重點 | 我們的模擬器怎麼對應 |
|---|---|
| 人力要加在瓶頸站才有效 | 儀表板會排出瓶頸站，並做「各站 +1 人」的比較實驗 |
| 脫水機批次和下班時間是 TAT 的主因之一 | 脫水機排程可設定（時間、程序、適用檢體），並統計「錯過上機時間」的件數和批次等待時間 |
| 同檢體的蠟塊不拆批，依程序分批 | 模型以檢體為單位上機，依容量裝載，並依程序區分 |
| 用 30 分鐘為單位的班表 | 用 Excel 輸入班別（可多個班別疊加），系統自動換算 |
| Arena 換參數很痛苦 | 參數全部放 Excel，儀表板可直接調整、多情境比較、成長情境自動跑 |
| 優先序沒做完整 | 急件在每一站都優先排隊 |
| 單段流程的理論下限 | 加入靜態產能分析（負荷率、節拍時間），不用跑模擬也能算 |
| RCPath TAT 指引（7 天 80%、10 天 90%） | TAT 目標可依檢體類型設定。預設值是台灣常見的工作天目標，屬於假設值 |
| 熱啟動、物流批次到件、次專科分工 | 列為後續階段 |
